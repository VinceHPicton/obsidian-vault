Using a Middleware type is more readable!
```go
type Middleware func(http.Handler) http.Handler

func LoggingMiddleware() Middleware {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			start := time.Now()
			next.ServeHTTP(w, r)
			log.Printf("%s %s %s", r.Method, r.URL.Path, time.Since(start))
		})
	}
}

func Chain(h http.Handler, mws ...Middleware) http.Handler {
	// apply in reverse so the first middleware in the list
	// ends up outermost (runs first on the way in)
	for i := len(mws) - 1; i >= 0; i-- {
		h = mws[i](h)
	}
	return h
}

func main() {
	mux := http.NewServeMux()
	mux.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) {
		w.Write([]byte("hello"))
	})

	handler := Chain(mux,
		LoggingMiddleware(),
		CORSMiddleware("http://localhost:8081"),
	)

	http.ListenAndServe(":8080", handler)
}
```

# Benefits?
### Consistent typing for a middleware chain/stack

CORSMiddlewareOLD has the signature func(http.Handler) http.Handler directly. That's fine standalone, but if you have other middleware (logging, auth, recovery, etc.) that also produce Middleware-typed values, CORSMiddlewareOLD doesn't fit into a []Middleware slice or a generic Chain(...) helper without wrapping it. CORSMiddleware() returns a Middleware, so it slots directly into that ecosystem:

```
```go
var stack = []Middleware{
    LoggingMiddleware(),
    CORSMiddleware(),
    AuthMiddleware(),
}

func Chain(h http.Handler, mws ...Middleware) http.Handler {
    for i := len(mws) - 1; i >= 0; i-- {
        h = mws[i](h)
    }
    return h
}
```


### You can add additional args to it

CORSMiddleware() is a function call that returns a Middleware, rather than being the middleware itself. Right now it takes no arguments, but that shape means you can later add parameters (allowed origin, allowed methods, a config struct) without changing the type signature everyone depends on:

```go
func CORSMiddleware(allowedOrigin string) Middleware {
    return func(next http.Handler) http.Handler {
        return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
            w.Header().Set("Access-Control-Allow-Origin", allowedOrigin)
            ...
        })
    }
}
```

With CORSMiddlewareOLD, since it's used directly as http.HandlerFunc(...)-producing function, adding config means either package-level vars (bad) or changing its signature to something incompatible with plain func(http.Handler) http.Handler usage patterns elsewhere.
