
```go
func (s *Server) Routes() {

	// Ungrouped / public routes — no shared middleware
	s.Router.HandleFunc("/dbping", s.middlewareExample(s.handleDBping())).Name(dbPingRouteName)

	// First group
	CORS := s.Router.NewRoute().Subrouter()
	CORS.Use(s.CORSMiddleware())

	CORS.Handle("/auth-attempt/start/login", s.authAttemptStartLoginHandler()).Methods(http.MethodPost).Name(authAttemptStartLoginRouteName)

	// Next group using first
	protectedCORS := CORS.NewRoute().Subrouter()
	protectedCORS.Use(s.authMiddleware())
	
	protectedCORS.HandleFunc("/users", s.userCreateHandler()).Methods(http.MethodPost).Name(userCreateRouteName)
}
```
- `s.Router` — root, no middleware. `/dbping` sits here ungrouped, so nothing runs but the handler itself.
- `CORS` — subrouter of root, adds CORS. Any route registered on it gets CORS checked first.
- `protectedCORS` — subrouter of `CORS`, adds auth. Routes here run CORS _then_ auth, then the handler.
So group nesting = middleware ordering. A route registered deeper in the chain automatically gets everything above it.



Middleware type def  and example middleware definition:
```go
type Middleware func(http.Handler) http.Handler

func CORSMiddleware() Middleware {
	return func(next http.Handler) http.Handler {
		return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
			w.Header().Set("Access-Control-Allow-Origin", "http://localhost:8081")
			if r.Method == http.MethodOptions {
				w.WriteHeader(http.StatusOK)
				return
			}
			next.ServeHTTP(w, r)
		})
	}
}
```

What's in server?
```go
type Server struct {
	DB           *sql.DB
	Router       *mux.Router
	Queries      *sqlc.Queries
	TokenManager *tokens.Manager
}

func (s *Server) authMiddleware() func(http.Handler) http.Handler {
	return AuthMiddleware(s.TokenManager)
}

func (s *Server) CORSMiddleware() func(http.Handler) http.Handler {
	return CORSMiddleware()
}
```
**Why the `s.XMiddleware()` wrappers exist**

- `CORSMiddleware()` — the _package-level_ function. Calling it returns a `Middleware` (which is a function which takes a http.Handle and returns a http.Handle) — it hasn't wrapped anything yet.
- `s.CORSMiddleware()` — CALLS CORSMiddleware() and returns the return value, which is http.Handler which is required by .Use(). The only reason it exists is to give `.Use()` something reachable off of `s` (Server), 
- More importantly for `authMiddleware` — to close over `s.TokenManager` so the middleware has access to server state it needs (the DB, token manager, etc.) without you having to pass those in manually at every route.
